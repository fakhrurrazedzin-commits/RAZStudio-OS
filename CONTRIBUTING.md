# Contributing

## Workflow

1. Read the [requirements](docs/requirements/Requirements.md) and relevant [architecture](docs/architecture/design.md).
2. Open an issue or architecture proposal for a material design change.
3. Keep changes bounded to one task or decision.
4. Run link and Markdown checks before submitting.
5. Record commands, exit codes and evidence for implementation tasks.

## Documentation rules

- Use normative language consistently: MUST, SHALL, SHOULD and MAY.
- Keep locked decisions in [decisions](docs/decisions/README.md).
- Do not duplicate architecture across multiple pages.
- Cross-link canonical documents.
- Never document fabricated test or hardware results.
